# Interview Notes

## Agent Gateway

**为什么不让模型直接写库？**

模型不掌握最新库存、权限和单据状态。模型负责理解，Java 负责确定性校验、草稿、确认、幂等和审计。

**用户上下文怎么传递？**

后端签发短期 `contextId`，工具调用时解析并恢复最小用户上下文，模型不接触登录 Token。

**如何防止重复下单？**

草稿 ID + 校验票据 + 数据库唯一作用域；重复请求返回已有结果。

## SSO

**为什么用 code？**

Token 不进入 URL。code 60 秒有效且只能兑换一次，降低浏览器历史、代理日志和 Referer 泄露风险。

**怎么防重放？**

timestamp 限制时间窗，nonce 使用后写入缓存，重复请求拒绝。

## Trace

**条码追溯和单据链追踪有什么区别？**

条码追溯是事件流，回答“这个条码去过哪里”；单据链是关系图，回答“这张单从哪来、流到哪里去”。

**递归怎么防死循环？**

维护 visited 集合，已经访问的节点不再展开；分支汇聚时去重。

## SF Express

**为什么两层成功判断？**

网关成功只代表请求格式、签名和权限通过；业务数据仍可能失败，必须继续判断业务 success。

**顺丰成功但本地回写失败怎么办？**

本地事务不能回滚外部订单。需要持久化调用状态、运单号和业务唯一号，提供查单、重试和定时对账。

## Auth and Permissions

**为什么前后端都要做权限？**

前端菜单只负责用户体验，后端接口必须再次校验。否则用户可以直接调用接口绕过菜单隐藏。

**SSO 登录后怎么进入业务菜单？**

SSO exchange 返回 token、用户和权限列表，前端保存 token，后端拦截器解析 token 后按角色校验接口权限。

**操作日志记录什么？**

登录、SSO 授权/兑换、顺丰调用等关键动作，记录用户、动作、结果和时间；生产环境还应补 traceId 和耗时。

## RAG

**为什么先用关键词检索？**

这个 Demo 用关键词和本地哈希 embedding 做混合检索，先跑通文档切分、权限过滤、TopK、引用和评测。生产环境可以把哈希 embedding 替换成真实 Embedding + 向量库，不改变上层问答协议。

当前也提供了 OpenAI-Compatible Embedding 适配器，配置 `rag.embedding.provider=openai` 后启用；外部调用失败会降级到哈希向量。

**怎么防止越权检索？**

检索前按用户角色过滤知识文档：PUBLIC 所有人可见，OPERATOR 仅业务员和管理员，ADMIN 仅管理员。引用来源也只返回过滤后的片段。

**怎么评测？**

内置问题集同时检查期望文档是否出现在 Top3，输出命中率和每个问题的 Top 标题。

**为什么要保留模板回答？**

没有外部模型 Key 时项目仍要能演示；同时 LLM 调用失败不能被当成 RAG 检索失败，应该降级到基于引用片段的模板回答。
